# Отдельный дизайн-стенд «Администрирование»

Стенд использует те же компоненты `src/features/admin/redesign`, что и основное приложение. `FixtureAdminProvider` подставляет локальные данные вместо `LiveAdminProvider`. Сетевой барьер стенда не даёт вызвать рабочий API. Основной `index.js` не заменяется.

Тестовые пользователи, отделы, роли и сервисы заданы в `apiFixture.ts`. Поиск, фильтры, открытие форм, локальная модерация и обычное редактирование работают в памяти. Неподдерживаемые операции завершаются явной ошибкой; fallback к API отсутствует. `networkBoundary.ts` блокирует случайные HTTP-запросы вне Metro. Настоящие учётные записи и секреты не нужны. Документы и история выпусков показаны локальными примерами; примеры OTA явно помечены. Это стенд дизайна, а не проверка авторизации/интеграций.

## Запуск

Из корня APP:

```powershell
npm run qa:admin
```

Сервер: `http://127.0.0.1:8110`. Web-версия: `http://127.0.0.1:8110/?theme=light` (тот же Metro обслуживает web и Android). Обёртка предпочитает установленный Node 24; для собственного пути предусмотрен `LEADER_NODE_BINARY`. Не запускайте второй Metro на том же порту.

## Android

```powershell
npm run build:admin-preview -- -Offline
adb install -r dev-builds/admin-preview/leader-product-admin-dev.apk
adb reverse tcp:8110 tcp:8110
adb shell am start -a android.intent.action.VIEW -d "leaderproduct-admin-dev://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8110" -p com.leaderproduct.admin.dev
```

- Имя: **Администрирование DEV**.
- Отдельный package: `com.leaderproduct.admin.dev`; обычное приложение и его SQLite не затрагиваются.
- Архитектуры: `arm64-v8a`, `x86_64` — телефон и эмулятор.
- Это development client: после первого подключения запоминает Metro, а сохранение JS/TS/стилей вызывает Fast Refresh. Компьютер с Metro должен работать и быть доступен телефону. Через интернет без Metro этот APK новые правки не получает; OTA production здесь отключён.
- Для телефона вместо `127.0.0.1` используйте LAN-IP компьютера и порт 8110. Например, текущий Wi-Fi-IP: `192.168.1.76` (может измениться).
- Локальное правило firewall `LeaderAdminPreviewLan-8110` разрешает порт только проектному Node 24, на Wi-Fi-адресе и из локальной подсети. Для другой машины/адреса: запустить `scripts/enable-admin-preview-lan.ps1 -HostAddress <IP>` от администратора Windows.
- Native-контейнер использует существующий отлаженный dev-проект и существующий ключ подписи. Скрипт временно меняет только applicationId, имя и URL-схему в игнорируемой папке `android/`, сохраняет резервные копии и восстанавливает байты в `finally`. Firebase/push в этом стенде не подключаются. Для изменений нативных модулей требуется новая сборка.
- Нативные бинарные зависимости общие с основным dev-клиентом; JS-entry открывает только администрирование. Это не минимизированный release APK.

## Выбранный дизайн — вариант 2

`AdminDirectory.tsx` реализует выбранный каталог: шапка на общей сетке Help (48/8/16), общий blur, поиск разделов, проверка сотрудника, меню темы и профиль. `AdminUsersPreview.tsx` — обновлённый плоский список и карточка пользователя. Поиск перенесён в шапку; статусы, отделы и счётчики находятся только в фильтре. Сотрудники с `employeeStatus=PENDING` стабильно располагаются первыми. Нажатие всей строки открывает карточку с личными данными, отделом, ролью, активностью и состоянием подключений. Сохранение и подтверждение/отклонение меняют только локальные тестовые данные. Перезагрузка стенда возвращает исходные данные.

Все разделы стенда теперь используют новый дизайн. `AdminOrganizationPreview.tsx` содержит отделы, сотрудников отдела, роли и наследование прав. `AdminServicesPreview.tsx` — доступность сервисов и ограничения по ролям/отделам. `AdminContentPreview.tsx` — чтение документов. `AdminUpdatesPreview.tsx` — история версий APK с вложенными раскрываемыми OTA и комментариями Git. Форм создания/публикации обновлений в этом разделе больше нет. Общие строки, редакторы, поля и переключатели находятся в `AdminDesignPrimitives.tsx`. Все нижние панели используют настоящий `HelpSheet` из `src/features/help/components/HelpPrimitives.tsx`; `DesignSheet` только ограничивает высоту прокручиваемого содержимого и передаёт состояние скролла. Самостоятельных нижних `Modal` в стенде больше нет. Полноэкранные карточки остаются отдельными экранами.

В `AdminUserIntegrations.tsx` добавлены поиск пользователя/физлица 1С, автоматическая подстановка физлица по выбранному пользователю и отображение ФИО. Telegram/MAX показывают ID из локальной модели `channelAccounts`. Форма сброса пароля выделена отдельно: скрытый ввод, повтор, минимум 6 символов как в исходной форме, подтверждение. В стенде это **симуляция**: пароль не сохраняется в fixture/localStorage, не передаётся серверу; хранится только отметка времени сброса. Примерные ID, ФИО 1С и документы являются синтетическими данными. Реальные API-интеграции и публикация выпусков не подключены.

## Общие переходы и шапки

Каталог остаётся смонтированным под открытым разделом и сохраняет поиск/позицию прокрутки. Все шесть разделов открываются и закрываются через `components/Navigation/AppSceneTransition.tsx`: это извлечённая реализация входа в чат «Помощи», которую сам Help теперь тоже использует. Один UI-thread progress управляет выездом экрана справа и сдвигом каталога; 240 мс вперёд, 220 мс назад, учёт reduced motion и защита от повторного возврата. Завершение обратной анимации предшествует размонтированию раздела.

`AdminSceneHeader.tsx` — общая прозрачная шапка каталога, списков и карточек с настоящим `AppEdgeBlur` и общей сеткой. Карточка пользователя переиспользует `DesignEditor`, как отделы, роли, сервисы, документы и формы подключения/пароля. Содержимое прокручивается под шапкой; отдельного непрозрачного верхнего блока у профиля больше нет. У каждого экрана собственный `ScreenBlurProvider`, чтобы сохранённый нижний экран не перехватывал blur-target.

Проверка: TypeScript без ошибок; 68 связанных Help navigation/screen тестов; браузер — вход/возврат с сохранением поиска, прозрачный header и `backdrop-filter`; Android — запись открытия/возврата, двойной Back, профиль при прокрутке и карточка отдела. Доказательства: `screenshots/60-section-motion-native.mp4`, `63-user-header-scrolled-native.png`, `66-header-comparison.png` в `docs/design/admin-redesign`. Изменения поступают в уже установленный dev APK через Fast Refresh.

## История обновлений — источник данных

Снимок `releaseHistory.generated.json` формируется командой `npm run qa:admin:history` и автоматически перед запуском стенда. Источник APK — локальные `dev-builds/releases/*/release-metadata.json`; комментарии — реальные `git log --no-merges` в диапазонах между коммитами сборок, с сохранением исходного текста и SHA. В текущем снимке 2 версии APK и 53 комментария с учётом примеров OTA. Старые синтетические записи выпусков удалены.

`createdAt` локальных метаданных — время сборки, поэтому UI честно пишет «Собрано». Часовой пояс отображения — Asia/Novosibirsk. Подтверждённого реестра публикаций OTA локально нет: вложенные OTA помечены «Пример», а их время подписано «Изменения от» (дата Git-коммита). Их последовательность и принадлежность не выдаются за фактическую историю публикаций. Данные уже разделяют `publishedAt`, `builtAt` и `changesAt`. При подключении реального реестра потребуется передавать фактические `publishedAt`, `runtimeVersion`, `displayVersion` и диапазон `commitSha` для каждой публикации. Если на другом компьютере нет локальных APK-артефактов, генератор сохраняет готовый снимок вместо очистки истории.

Основное приложение теперь использует этот же интерфейс с реальными данными и существующими административными API. Тестовый APK получает общие JS-изменения через Fast Refresh; примерные данные остаются только в стенде.

Проверено в браузере и Android: новый список/карточка, поиск, сохранение отдела, подтверждение профиля, фильтр по отделу, отсутствие панели статусов над списком и приоритет ожидающих проверки. Итоговые снимки: `docs/design/admin-redesign/screenshots/19-users-final-native.png`, `20-directory-final-native.png`. Отчёт — последний раздел Admin в корневом `design-qa.md`.
