## Разделение черновиков и очереди — 07.10.2026, dev OTA 0.1.32.11

Причина: массовая отправка выбирала `ON_DEVICE` и сама меняла `SAVE` на `SUBMIT`.
Счётчик кнопки включал все локальные документы, а не очередь.

- Общая проверка допуска требует одновременно явного `intent: SUBMIT`, статуса
  `READY_TO_SEND` или `SEND_ERROR` и отсутствия `requiresReview`.
- Принудительная отправка (`force`) больше не превращает сохранение в отправку.
  Заполнение обязательных полей также не является разрешением отправить заказ.
- Mobile и web показывают на кнопке только очередь. Отправляемый документ остаётся
  в счётчике до завершения запроса, чтобы кнопка с индикатором не исчезала.
- `PRICE_REVIEW` можно отправить только после выбора политики цен для конкретного
  документа; массовое действие не подтверждает новые цены за пользователя.
- Полные/неполные черновики не валидируются, не меняют статус и не записываются
  массовой отправкой. Копию документа сначала нужно отдельно поставить в очередь.
- Сетевая ошибка сохраняет очередь и прежнюю идентичность операции для повтора.

Проверки: смешанный список черновиков/очереди/ошибок/изменившихся цен; `SAVE` с
разными статусами; адресное подтверждение цен; счётчик во время запроса; копия,
явно добавленная в очередь; существующие проверки обрыва сети и перезапуска.

Результат: 84 теста в четырёх наборах — успешно; `tsc --noEmit` и проверка

### Результат реализации

- `GET /api/client-orders/purchase-history?organizationGuid=…&counterpartyGuid=…`:
  защищён существующими проверками сессии, статуса и доступа к заказам.
  `version=customer-purchases-v1`, `coverageFrom`, `asOf`, `fetchedAt`,
  `items: [{ productGuid, lastPurchasedDate }]`. Серверный кеш — 5 минут,
  ключ включает пользователя и обе ссылки. Ошибка/старое расширение дают 503,
  а не ложную пустую историю.
- Источник — LP `/counterparty-card?mode=purchase-history`; тяжёлая аналитика
  карточки не выполняется. Фильтр `/products?purchasedOnly=true` передаётся
  в 1С и проверяет версию поддержки, не допускает незаметного отбора всех товаров.
- SQLite v4 добавляет две таблицы истории, без очистки каталога/черновиков.
  Фильтр применяется до LIMIT/OFFSET, сохраняет приоритет цены и совместим с FTS.
  При невозможности записать кеш онлайн-подбор продолжает работать через API.
- История конкретного клиента скачивается при открытии подбора онлайн, затем
  доступна офлайн. До первой такой загрузки фильтр недоступен и показана причина.
  Повторное открытие в пределах 5 минут не загружает историю снова.
- Общий `SearchPickerScreen` используется повторно; продуктовые фильтры —
  иконки 22 px в кнопках 40×40, как закрытие. Для других справочников подписи
  сохранены. В web используются существующие MUI IconButton/Tooltip.
- При сбое загрузки нельзя принять старые строки за результат нового фильтра:
  список сбрасывается, показана кнопка повтора без технического сообщения.
