# Диалоги подключений профиля

Изменение APP, 07.11.2026: выбор почтового провайдера и ввод учётных данных 1С открываются в общем модальном компоненте `ConnectionDialog`. Внутренний повторяющийся заголовок «Подключения Демо» в блоке почты удалён. Разделы «1С» и «Почта» остаются в существующем списке подключений профиля и раскрываются независимо: открытие одного больше не закрывает другой. После первого раскрытия содержимое раздела сохраняется смонтированным: повторное раскрытие не запускает новый fetch/loader только из-за сворачивания. `ConnectionSectionVisibilityContext` не позволяет скрытому сохранённому разделу показывать модальный диалог; скрытое содержимое также исключено из accessibility дерева.

## Общий диалог

На desktop web `ConnectionDialog` переиспользует `AppDesktopDialog` с максимальной шириной 480. На компактном web/native используется существующий стек React Native Modal с безопасными отступами, ограниченной высотой, прокручиваемым содержимым и KeyboardAvoidingView; дополнительный native-модуль не требуется. Закрытие через кнопку, фон и системный back передаётся владельцу формы. Пока форма занята, закрытие блокируется через busy; черновиками и авторизацией управляет вызывающий компонент.

## Почта и оформление действий

«Подключить»/«Добавить» открывают выбор доступного провайдера Mail.ru или Яндекс. Кнопка подключения доступна после выбора; отмена и закрытие сбрасывают выбор. Уже выбранный в демо провайдер исключён из доступного списка. Локальное «Отвязать» удаляет его из демонстрационного состояния.

Почта по-прежнему является интерактивным дизайн-превью: реальная авторизация ящика, чтение писем и сохранение почтовых credentials не добавлены. В строке справа показывается зелёное «Подключено» перед компактной кнопкой отвязки, как у 1С; строка не переносится, длинное название сокращается многоточием, чтобы статус и действие сохранялись справа на узком экране. Прежняя подпись «Подключено в демо» под названием удалена. Несмотря на это визуальное название, состояние почты остаётся локальным превью, а не действующей интеграцией.

Кнопки открытия «Подключить» у 1С и почты, «Добавить» и «Отвязать» используют текстовый режим без постоянной рамки и фона; кнопки открытия находятся слева. Общий `ConnectionAction` подключает существующий web-feedback для hover/focus/нажатия; основная кнопка отправки формы внутри диалога сохраняет заливку и прежнюю семантику. Disabled-действие исключено из общего appControl hover-feedback, а внешняя Paper-обёртка получает aria-disabled. Внешние обёртки не дублируют кнопку.

## Подключение 1С

Реальная форма 1С остаётся владельцем серверной авторизации и личного соединения сотрудника. Повторный блок «База» с названием внутри credential-формы удалён; выбор базы при наличии нескольких доступных баз остаётся в списке подключений. Она показывается через тот же `ConnectionDialog`, а не разворачивается внутри списка. Данные учётной записи не записываются в документацию, логи и архив исходников. При обычном входе неподключённая база показывает кнопку подключения. Защищённый вход с initialBase/onConnected однократно открывает диалог после загрузки доступной базы. Ошибка авторизации остаётся в диалоге; подтверждённый сервером успех закрывает его перед существующим onConnected(signal), включая возврат в исходный Help-чат. Синхронный busy guard предотвращает повторный запрос и ручное закрытие в процессе.

Отмена/закрытие размонтирует форму и очищает введённые данные; уход приложения в background также закрывает форму и очищает поля. Смена focus/аккаунта и размонтирование сохраняют AbortController/epoch-защиту от устаревших результатов. Пароль очищается из поля при отправке. Статус соединения и отвязки обновляется только по успешному серверному ответу, без оптимистического фиктивного подключения. Отвязка отображается текстовым действием.

## Проверки и восстановление

Пройдено 39 тестов в 7 наборах; после финальной адаптации почтовой строки повторно пройдены 3 пересекающихся mail-теста. TypeScript без ошибок, Expo Doctor 20/20, зависимости актуальны. Оба финальных Metro bundle вернули HTTP 200 и содержат ConnectionDialog. Отдельная browser/native visual QA не выполнялась. Доказательства сохраняются в `.dev-runtime/profile-connection-dialog/final-proof.json`. Нельзя считать наличие диалога доказательством успешной реальной авторизации почты или сотрудника в 1С. Анонимная read-only диагностика 1С в 11:53:34 UTC подтвердила готовность dev API/worker, каталога, vault и сети, но upstream MCP torg2026 ответил HTTP 500 «Начало сеанса с информационной базой запрещено.» Владелец подтвердил техобслуживание базы и попросил пропустить дальнейшую диагностику. Срок завершения и снятие ограничения не проверялись; credentials сотрудника не использовались и запрет не снимался. Подробный статус записан в API `docs/onec-personal-connections.md`. API deployment, OTA, native release и перезапуск основных Metro/T3 не выполняются.

Код находится в `src/features/profile/ui`: `ConnectionDialog`, `ConnectionPrimitives`, `MailConnectionPreview`, `ProfileConnections`, `ProfileOnecConnections`, `OnecConnectionForm`. Техническая инструкция хранится в Nextcloud с доступом IT/admin; ограниченный архив исходников и доказательств — в закрытой папке «Восстановление компании». Снимок может включать сохранённые конкурентные изменения; перед восстановлением согласовать их с актуальной веткой. Env, ключи, пароли, токены, реальные почтовые данные, переписки и скриншоты в архив не включаются.
