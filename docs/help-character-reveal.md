# Плавный вывод ответа ИИ словами

Обновление для обращения №85, 07.11.2026. Legacy- и live-ветки используют общий `HelpStreamingAnswer` и `helpTextReveal` / `useHelpTextReveal`. На клиенте меняется только видимый префикс: серверный текст и сохранённая история остаются полными. Дополнительно серверный guard сохраняет уже проверенный префикс при временном hold незавершённого слова.

## Быстрый вывод без очереди после завершения

Общий целевой такт остаётся 20 мс. Новое добавление догоняется в коротком планируемом окне 80 мс, преимущественно целыми словами и фразами. Пробелы и пунктуация задают границы; округление вперёд ограничено 12 графемами, поэтому длинный URL, код или текст без пробелов использует ограниченный Unicode fallback. Границы графем определяются через Intl.Segmenter с резервной обработкой surrogate/combining/ZWJ/flag/CRLF случаев.

После завершения полный авторитетный ответ показывается сразу: FINAL_MS=0. Прежние 50 графем/с, live-окно 1600 мс и финальный догон 1200 мс больше не определяют поведение. 80 мс — параметр планирования интерфейса, а не гарантия частоты кадров или сетевой задержки. Перед обработкой нового чанка учитывается уже прошедшее время.

Первый смонтированный, исторический или кешированный снимок показывается сразу, включая активный ответ после remount виртуализированной строки. Анимируются последующие добавления. Новый identity, замена/отзыв текста, ошибка/остановка и отключение эффекта немедленно показывают актуальный снимок. Native-владелец прокрутки/клавиатуры и существующее измерение текста сохраняются.

## Сохранение проверенного текста при hold

Диагностика №85 выявила поведение серверного guard: временный hold незавершённого слова мог отправить пустой draftText, после чего следующая разрешённая версия возвращала текст. Воспроизведение префиксов итогового ответа показало такие позиции hold. Точные сетевые чанки исторического запроса не сохранялись, поэтому это не покадровая трасса того запроса; пользовательский текст не копируется в документацию и архив.

При hold guard сохраняет только последний уже проверенный префикс, если новый draft продолжает его и повторная проверка префикса всё ещё разрешает показ. Удерживаемый suffix не показывается. Подтверждённый block, явный отзыв, замена/исправление текста и недопустимый прежний префикс по-прежнему очищают публичный draft. После ошибки записи новое значение не становится последним успешно переданным префиксом.

Исходный progress writer вызывается и для hold: lease, source/access, proof и ticket-state fences не обходятся. Обработка публичного analysis и финальная проверка ответа сохраняются. ## История, доступность и стабильность компонентов

Один общий таймер работает только при активных подписчиках. Reduced motion, background/скрытая web-вкладка, неактивная область Help и native screen reader отключают эффект, показывая полный актуальный текст; подписки и таймер освобождаются.

В установленной react-native-web 0.21.4 isScreenReaderEnabled является constant-true заглушкой. Поэтому screenReader query/event используются только на native; web учитывает visibility и настоящий reduced motion через useHelpReducedMotion / matchMedia. Достоверное обнаружение web screen reader не заявляется. Это сохраняет исправление из `.dev-runtime/help-character-reveal-web-fix/`.

Legacy держит общий HelpStreamingAnswer смонтированным даже при пустом тексте и завершении, без дополнительной arrival-анимации. Live Markdown-блоки сохраняются при завершении; готовая история разбирается обычным способом. Публичный analysis использует тот же механизм отображения; новый источник внутренних рассуждений не добавляется.

Отдельное ограничение: первое HTML-вложение может переключить HelpAssistantMessage на HelpHtmlMessageRoute и перемонтировать ответ. Начальный снимок при remount показывается сразу по существующему контракту. HTML-ветка этой правкой не меняется и отдельно визуально не проверяется.

Иконка чата, время/статус, доступная подпись, вложения и действия сохраняются. Сопоставление пары, pending/ACK и исходные ID остаются прежними. См.
