# Единый блок вопроса ИИ и ответа пользователя

Изменение APP, 07.11.2026. Подтверждённый ответ на анкету показывается внутри блока вопроса ИИ. В хранилище остаются два исходных сообщения с отдельными ID и sequence; объединение выполняется только при построении интерфейса. Миграция, удаление истории и переписывание outbox не требуются.

## Связь сообщений

Новые отправки анкеты используют существующий `replyToId`, указывающий на сообщение ИИ с вопросами. Текст ответа сохраняет обычный формат `formatHelpQuestionAnswers`. Это та же долговечная отправка, включая файлы и существующую защиту черновиков; новое серверное API не добавляется.

Для уже записанной истории связь выводится консервативно из полного точного формата анкеты, владельца обращения, ticket ID и соседних sequence. Обычный текст, частичный ответ, неоднозначные границы вопросов, повторяющиеся ID/sequence, чужой автор, другое обращение и конфликтующий replyToId не превращаются в анкетный ответ. Если нужной пары нет в текущем окне истории, сообщения остаются отдельными. Ожидающий отправки ответ с explicit replyToId визуально помещается в тот же блок через отдельную pending-связь, сохраняя статус и повтор отправки. Допускается одна однозначная pending-запись для последнего загруженного сообщения-вопроса; уже принятый clientMessageId исключается. Такая связь не превращает outbox-запись в подтверждённое сообщение и не участвует в read tracking или сохранённой истории. Отсутствующие ответы не придумываются.

## Отображение и действия

Подтверждённая пара становится одной строкой ИИ в timeline. Ответ отрисовывается существующим `HelpMessageBubble`, сохраняя идентичность пользовательского сообщения, его файлы, реакции и доступные действия. При переходе pending → подтверждённый ответ сохраняется тот же тип внутреннего HelpMessageBubble; общий resolveQuestionMedia поддерживает локальные localUri до загрузки файлов. Пользователь видит вопросы и свои ответы в одном блоке; ввод и отправка по-прежнему принадлежат существующей панели вопросов и composer.

Скрытый как отдельная строка ответ сохраняет alias своего ID/sequence в общей строке. Поиск, переход к сообщению, отметка непрочитанного, read tracking и восстановление scroll anchor находят исходный ответ через этот alias. Это визуальное объединение, не новый участник истории и не новое сообщение от ИИ. Соседние Heading и MessageArrival используют разные ключи (`heading:runId` и `answer:runId`), устраняя duplicate-key предупреждение при streaming/completed/stopped и смене run.

## Компактная строка вопроса и ответа

Слева находится иконка чата, вопрос расположен сверху, ответ — непосредственно следующей строкой без отдельной видимой подписи «Ваш ответ». Справа один раз показываются время и статус доставки. Вопрос и ответ всегда видны полностью: стрелка раскрытия, expanded-state и ограничения строк удалены. Доступная подпись ответа, вложения, реакции и действия сохраняются.

Это представление внутри существующего HelpMessageBubble: сопоставление сообщений, pending/ACK, outbox и исходные ID/sequence остаются прежними. Проверки последнего уточнения входят в `.dev-runtime/help-character-reveal/` вместе с посимвольным отображением ИИ (86 тестов / 5 наборов, TypeScript, Expo Doctor 20/20, оба Metro bundle HTTP 200; без visual QA); предыдущие результаты ниже описывают базовую реализацию объединения.

Связанная документация: [Оформление сообщений Help](help-message-presentation.md). В Nextcloud базовая инструкция находится в «Материалы компании/Оформление сообщений Help — 2026-11-07».

## Проверки и восстановление

Пройдено 352 теста в 9 наборах, TypeScript без ошибок, Expo Doctor 20/20, зависимости актуальны. Оба финальных Metro bundle вернули HTTP 200 и содержат exchange, pending-связь и отдельные префиксы ключей. Доказательства сохраняются в `.dev-runtime/help-question-exchange/final-proof.json` и связанных журналах. Проверены связывание, неполные страницы, pending/ACK, навигация по ID/sequence и регрессии duplicate-key. Финальное review не выявило блокирующих проблем, включая идентичность Bubble/resolver при ACK. Отдельная browser/native visual QA не выполнялась. API deployment, OTA, native release и перезапуск основных Metro/T3 не выполняются.

Техническая инструкция хранится в Nextcloud с доступом IT/admin; ограниченный архив текущих исходников, тестов и доказательств — в закрытой папке «Восстановление компании». Снимок может включать сохранённые конкурентные изменения; перед восстановлением согласовать его с актуальной веткой. Env, credentials, токены, реальные диалоги, пользовательские вложения и скриншоты в архив не включаются.
