# Общий просмотрщик ссылок: реализация и восстановление

Состояние на 06.11.2026. Существующий EntityCardProvider расширен до общего AppViewerProvider без второго глобального провайдера. Виды кадров: entity, connection, html, web. Совместимый старый API сохранён. HelpViewerLayout, HelpHeaderFrame/Overlay, портал и анимация переиспользованы. Учётная запись, активный кадр, сессия и исходное сообщение ограждают поздние ответы. Закрытие или смена источника HTML снимает его кадр и дочерние страницы.

src/shared/appLinks.ts централизует типизированный разбор обычных http/https, leaderproduct entity, Help и HTML-ссылок, mailto/tel. Приватный permalink ведёт через существующий защищённый маршрут Help: он не загружает произвольное вложение по UUID. HelpMarkdown обрабатывает сохранённые и новые сообщения одинаково. Нативные WebView остаются смонтированными под дочерними карточками, сохраняя историю и состояние; изменение текущего URL не меняет начальный source. Назад: меню → история сайта → стек просмотра. Смена аккаунта уничтожает стек.

WebPageContent использует существующий react-native-webview без новой зависимости. Настоящие сайты имеют JavaScript/DOM storage в отдельной incognito-сессии, без заголовков авторизации приложения, токенов и native message bridge. Файлы и mixed content запрещены. Нестандартные разрешённые действия сайта требуют явного подтверждения в нативном интерфейсе, так как Android navigationType=other не доказывает пользовательский клик. Обычные http/https-переходы остаются внутри страницы. Есть загрузка, ошибки, повтор, восстановление после завершения renderer process; поздние события скрытого кадра не управляют активной шапкой. Верхний отступ защищает элементы чужого сайта от перекрытия шапкой без переписывания DOM/CSS сайта.

Веб-iframe имеет allow-scripts/allow-forms, но без allow-same-origin, поэтому редирект на домен самого приложения не получает его storage. Родитель не читает DOM и историю чужого сайта; внешний браузер доступен постоянно, а действия подписаны как исходная ссылка. Это ограничение платформы, а не гарантированная успешная загрузка любого ресурса.

HTML по-прежнему инертен: JavaScript/bridge/сеть выключены, CSP и sandbox сохраняются. Server sanitizer разрешает http/https только в a[href] через allowedSchemesByTag, а не глобально; ссылки с credentials, управляющими символами или backslash удаляются. Remote img, scripts, forms, frames, CSS URL остаются запрещены. В полном HTML native перехватывает только допустимые объявленные ссылки; web использует кнопки приложения вне sandbox. Компактный HTML с единственной веб-ссылкой получает внешний press-target с сохранением touch-through и фиксированной геометрии; entity-действие имеет приоритет.

Слой этой функции: leaderproductapi:help-web-links-dev-20261106-r2. При финальной проверке оба здоровых процесса уже используют параллельный avatar-cache-dev-20261106-r1, сохранивший точный SHA модуля этой функции. Изменён только dist/modules/help/help.html.js поверх реального help-quality-v2-dev-20261106-r1 (через r1). Исходник до правки транспилировался байт-в-байт в актуальный runtime. Существующие OpenAI/1С/шлюзы/качество/ACL/lease/OTA и приватные Compose/env/mounts сохранены. Нет миграций, business writes, нового native runtime, OTA или перезапуска T3/main Metro. Будущие API-сборки должны сохранять этот модуль вместе со всеми прежними актуальными слоями, не деплоить всю незавершённую ветку.

Доказательства: .dev-runtime/help-web81/. Настоящий runtime прочитал сохранённую ссылку обращения81, проверил создание/повторную валидацию синтетического артефакта в памяти и удаление опасных ресурсов, не меняя сообщений. Визуальная проверка Android не завершена: Device MCP сначала потерял захват, затем сообщил Android automation helper is still holding device automation ownership; управление устройством остановлено. Изолированный qa/web-viewer-preview не является проверкой авторизованного обращения81 и не заменяет реальный экран.

Исходники, минимальный runtime-layer, хэши и доказательства сохранены в закрытой папке Nextcloud «Восстановление компании». Это снимок функции, не полная резервная копия сервера. Учётные данные хранятся отдельно в зашифрованном архиве доступа. При восстановлении согласовать сохранённые конкурентные изменения с текущей веткой.
