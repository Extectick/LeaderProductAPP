# Геомаршруты без Firebase — обычные Android-телефоны

Работа в dev. Единственный сборщик — Traccar; второй GPS-сервис не запускается.
Пауза и выход пользователя имеют приоритет над восстановлением. Ограничения
Android/Force Stop не обходятся. Production и 1С не затрагиваются.

## Реализация

- [x] Нативный канал команд: пережить задержку инициализации SDK, восстановить
  соединение при появлении сети, ограничить повторы и отменять работу при паузе.
- [x] Диагностика: батарея, уведомления, точность/фоновые разрешения, GPS,
  реальное состояние канала команд отдельно от времени координаты.
- [x] Профиль: понятные предупреждения и кнопки системных настроек;
  повторная проверка после возвращения в приложение.
- [x] Сериализация запуска/остановки/восстановления, отмена позднего запуска.
- [x] Восстановление со сохранённым ключом без сети; серверная перепроверка ключа
  не должна останавливать уже работающий сборщик из-за временной ошибки сети.
- [x] Убрать ложное «успешно отправлено» из эвристик диагностических логов.
- [x] API: выбирать недавно отвечавшее устройство, сохранять совместимость со
  старыми APK; время команд не подменяет время GPS.
- [x] Регрессионные тесты APP/API и TypeScript.
- [x] Компиляция Android.

## Детали надёжности

- Канал команд ожидает инициализацию Traccar при старте Android-процесса.
  Он не запускает второй сборщик и не обходит пользовательскую паузу.
- Возврат сети прерывает длинную задержку повторов. При нормальной связи —
  интервал сервера (сейчас 15 секунд), при сбое — до 120 секунд.
- Отказ ключа (401/403) сохраняется между перезапусками процесса: новая попытка
  старта возможна после успешного bootstrap авторизованной сессии.
- При временном отсутствии сети/5xx допускается существующий ключ; при явном
  отказе доступа и при отсутствии ключа — нет. Проверка bootstrap ограничена 10 с.
- Пауза сохраняется сразу и останавливает SDK до ожидания сетевых операций.
  Отложенный start/restore не может включить его обратно.
- Автопроверка при входе/возврате и раз в минуту только на переднем плане.
  Она не запрашивает разрешения диалогами. Неизменная конфигурация не пересоздаёт SDK.
- «Связь с API» — только подтверждённый Upload response 2xx (включая heartbeat),
  а не время координаты. SDK не предоставляет время записи точки через JS:
  неизвестное значение не выдумывается из строк логов.
- Настройка батареи открывается только по нажатию пользователя. На Android
  разных производителей названия и дополнительные ограничения отличаются.

Основание: [Traccar SDK](https://www.traccar.org/traccar-client-sdk/),
[ограничения Android Doze](https://developer.android.com/training/monitoring-device-state/doze-standby).
Версия SDK остаётся 1.0.10; новые библиотеки не добавлены.

## Приёмка на физическом телефоне (отдельно от unit-тестов)

- [ ] Уведомления, точная геолокация «Всегда», физическая активность разрешены.
- [ ] Батарея «Без ограничений»; для производителя при необходимости — автозапуск.
- [ ] Восемь часов: движение, неподвижность, погашенный экран; измерить батарею.
- [ ] Потеря сети и возврат: очередь догружается, команды снова принимаются.
- [ ] Перезапуск процесса, перезагрузка, обновление APK.
- [ ] Пауза/выход во время запуска: сборщик не возобновляется сам.
- [ ] Force Stop: нет обещания удалённого пробуждения; требуется открыть приложение.
- [ ] Отозванный ключ: нет бесконечных повторов; восстановление только после
  успешной авторизованной регистрации устройства.

Новое нативное поведение требует нового APK. OTA само по себе его не добавит.

  и ограничения батареи; затем выполнить отдельную приёмку на физическом телефоне.
