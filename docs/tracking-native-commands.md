# Геомаршруты: команды без Firebase (dev, APK 0.1.28 / 27)

## Почему запрос не работал

В dev отсутствовали Firebase и push-токены. Запросы создавались, но команда не доходила до телефона; через 30 секунд показывался таймаут. Обычный трекер продолжал присылать точки/heartbeat.

## Реализация

- Android `LeaderTrackingCommands` стартует в Application независимо от React Native bridge, включая перезапуск процесса Traccar/загрузку телефона.
- Пока Traccar включён, проверка команд POST `/tracking/native/commands` каждые 15 секунд. Используется существующий ограниченный credential, не access/refresh JWT. Новый сборщик GPS и второй foreground service не создаются.
- Команда доступна только назначенному устройству. API хранит её до 60 секунд; SDK получает разовую позицию, ограниченную оставшимся временем (не более 35 секунд). При паузе разовый запрос отменяется.
- API завершает запрос только точкой с назначенного устройства, полученной после создания запроса. Повторная доставка команды не запускает второй параллельный запрос.
- `lastCommandPollAt` отдельно от GPS: проверка команд не выдаётся за свежую позицию.
- Ошибки разрешений/GPS возвращаются явно. Неудачные HTTP-запросы повторяются с задержкой до 120 секунд, а 401/403 останавливают трекер до повторного bootstrap при входе.
- Native credential не пишется в URL, переходы по HTTP redirect запрещены. Kafka скрывает query/body native endpoints и bootstrap.
- При включённом трекинге канал удерживает частичный wake lock с ограниченным сроком, продлеваемым при успешных проверках. При паузе/ошибке сети удержание снимается. Это увеличивает энергопотребление относительно одного трекера в неподвижности.
- Force Stop обойти нельзя. Ограничения Doze/OEM могут задерживать сеть; для фонового теста включить «Батарея — Без ограничений». 60 секунд — срок ожидания, не гарантия ответа.
- Старые APK поддерживают прямой запрос себя в открытом приложении (при наличии соответствующего JS). Для удалённого запроса без push требуется новый APK и хотя бы один успешный command poll после установки. При отсутствии обоих каналов API возвращает `DEVICE_UPDATE_REQUIRED`.

## Интерфейс

- Итоги дня закреплены у нижнего края, безопасная зона Android находится внутри панели.
- Дата/стрелки/календарь видны в свёрнутом и раскрытом виде. Кнопки не переключают панель.
- Плоская виртуализированная хронология; серверные cursor-страницы заказов дозагружаются без повторного чтения GPS. Локальные остановки добавляются в хронологическом порядке.
- Обновление — иконка в шапке итогов, без нижней текстовой кнопки.

## Проверка перед пилотом

- Автотесты APP/API: self/native delivery, RBAC, изоляция команд и ошибок устройства, таймаут-гонка, пагинация, отсутствие credential в Kafka.
- Native compilation и отдельная сборка dev APK; prod не изменять.
- На реальном телефоне: запрос из другого устройства/браузера, затем свёрнутое приложение, погашенный экран и неподвижность 30+ минут; выключение GPS; потеря/восстановление сети; пауза; перезагрузка; отзыв credential. Проверять время и точность фактической точки, а не статус присутствия.
- Сравнить расход батареи за рабочий день. Без полевого теста не считать фоновую доставку гарантированной.
