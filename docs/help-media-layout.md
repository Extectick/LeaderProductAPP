# Адаптивные фотографии и подписи Help

Реализовано в APP через Metro 07.11.2026. Основание: в обращении №63 портретное изображение ограничивало ширину всей подписи, а прежний предел высоты 350 dp оставлял снимок слишком мелким на большом мониторе.

## Геометрия сообщения

`HelpMessageBubble` рассчитывает место по измеренной строке сообщения. Исходящее сообщение использует до 86% ширины строки; входящее — ширину строки за вычетом 36 dp для аватара и промежутка. Фото с текстом, файловой частью или закрытием обращения получает эту доступную ширину независимо от пропорций фотографии. Подпись больше не наследует узкую ширину портретного снимка.

Изображение расположено по центру блока. Сообщение только с фото сохраняет естественную ширину изображения без лишнего пустого фона. `helpMediaPreviewBounds` ограничивает доступную ширину превью 640 dp и высоту одиночного изображения `min(width × 1.65, 760)`. Размер зависит от реальной колонки чата, включая боковую панель, а не от полной ширины монитора. Узкая колонка на большом экране не получает широкое изображение с горизонтальным переполнением.

`helpAlbumLayout` рассчитывает геометрию по сохранённым размерам вложения, до декодирования. Для одиночного фото сохраняются пропорции и режим contain; текст внутри снимка не обрезается. Неизвестные размеры сохраняют прежнюю квадратную оценку. Альбомы из нескольких фотографий используют прежнюю композицию и ограниченный crop миниатюр. Каждое вложение сохраняет свой порядок, доступную цель нажатия и измеренный origin для галереи.

Высота окна/клавиатуры и события загрузки изображения не являются входами расчёта превью. Это предотвращает изменение размеров уже показанного сообщения при появлении IME или получении пикселей. Поворот устройства или изменение доступной ширины колонки закономерно перестраивают геометрию. Новый механизм прокрутки, JS scroll-компенсация или второй владелец движения не добавлены.

## Закрытие галереи на web

`HelpGallery` обрабатывает основной клик мыши по чёрному полю вне фактически отображаемого изображения. Граница вычисляется с учётом contain, zoom и pan. Такое действие вызывает существующий `finish(false)` и штатную анимацию закрытия. Клик по изображению, drag, touch и остальные кнопки мыши не становятся закрытием галереи. Существующие жесты и анимация переиспользуются.

## Проверка и границы доказательств

Прошли 124 теста в 4 наборах: `helpMedia`, `helpMessageBubble`, `helpAlbumLayout`, `helpImageAlbum`; TypeScript, Expo dependency check и Expo Doctor 20/20. Покрыты разделение ширины подписи и фото, исходящий/входящий вариант, фото без подписи, реальные пределы колонки, соотношение сторон, прежний максимум 10 фото в альбоме, независимость от загрузки и галерейные клики.

В браузере проверены настоящие компоненты в изолированном `qa/help-preview/MediaMessagePreview.tsx` с синтетическими данными. При 2560×1440 портрет 1080×2400 отображается 342×760, подпись имеет ширину 731 px. Клик по фото сохраняет галерею открытой; клики по левому и правому чёрному полю запускают существующую анимацию и затем удаляют галерею. Зафиксирована промежуточная opacity 0.992, поэтому закрытие не было мгновенным размонтированием. Это проверка компонентов, не авторизованный сценарий обращения №63.

Мобильный web проверен при 390×844: фото 233.70×519.35, подпись 292.76 px, горизонтального переполнения нет. При 320×640: фото 189.01×420.02, подпись 232.55 px; входящая подпись 238 px, входящее сообщение только с фото имеет естественную ширину 193.05 px. Нативная Android-визуальная проверка не выполнялась. Android-бандл основного Metro собран с HTTP 200 (41 395 903 байта); это подтверждает сборку, но не визуальное поведение на телефоне.

Новый native runtime, API-развёртывание и OTA для этой правки не требуются и не выполнялись. Основной Metro 8081/T3 и данные приложения сохранены. Изолированный QA Metro 8131 остановлен, открытая вкладка проверки закрыта. Приватные журналы проверки: `.dev-runtime/help-media63/`; журналы не содержат исходной переписки или изображений пользователя.

## Восстановление

Ключевые файлы: `helpAlbumLayout.ts`, `components/HelpImageAlbum.tsx`, `components/HelpMessageBubble.tsx`, `components/HelpMedia.tsx` относительно каталога `src/features/help`; связанные тесты и синтетический fixture включены в отдельный снимок исходников. Снимок может содержать сохранённые конкурентные изменения этих файлов: согласовать их с текущей веткой, а не заменять весь checkout.

Техническая инструкция публикуется в Nextcloud с доступом IT/admin. Снимок исходников и проверенные SHA-256 сохраняются отдельно в закрытой папке «Восстановление компании». Архив не содержит env, ключей, паролей, токенов, сырых диалогов, пользовательских снимков или скриншотов проверки. Учётные данные находятся в отдельном зашифрованном архиве доступа.
