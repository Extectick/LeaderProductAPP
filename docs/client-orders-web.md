# Заказы выбранного контрагента — WEB PC, 9 ноября 2026

Актуальный сценарий WEB PC заменяет прежний отдельный «Журнал». Выберите контрагента слева: справа сразу открывается вкладка «Документы» с его заказами и черновиками в выбранной организации. Отдельные desktop-панель журнала и ссылки на неё удалены. Вкладка «Точки доставки» остаётся рядом; выбор организации — справа. Узкий WEB сохраняет прежний отдельный журнал, native-путь не меняется.

## Действия пользователя

1. Выберите организацию справа и клиента слева. В «Документах» доступны поиск, фильтры «Все», «Черновики», «В очереди», обновление и дозагрузка.
2. Нажмите на документ, чтобы открыть существующий редактор. Возврат к клиентам сохраняет выбранного контрагента/организацию, вкладку, поисковые поля и локальный контекст текущего смонтированного экрана. Это сохранение при переходе в редактор и обратно, а не новая гарантия восстановления после перезагрузки браузера.
3. Для нового заказа нажмите «Новый заказ». Если точка ещё не выбрана, сначала открывается вкладка «Точки доставки». Выберите адрес и повторно нажмите «Новый заказ». Проверка несохранённых изменений и прежнее создание остаются.
4. Подходящий черновик можно продолжить прежним действием. Контекстное меню документа и существующая отправка очереди устройства сохранены.

## Контракт данных и сохранение контекста

`useCustomerDocuments` задаёт полный набор фильтров через существующий workspace: requesting account + GUID контрагента + GUID организации + текст поиска + статус. Старые фильтры отдельного журнала по дате/сумме/складу и прочим полям сбрасываются для этого scoped view, чтобы не скрывать документы выбранного клиента. Сетевые запросы, кеш, локальные черновики и проверка доступа остаются в workspace; нового API и прямых сетевых запросов в контроллере нет. Документы загружаются прежними страницами по 20, клиенты слева — по 60 на WEB PC, точки доставки — по 30. Локальные черновики по-прежнему объединяет workspace.

Строки выдаются только для активного готового scope после совпадения фильтров, hydration кеша и завершения reset/loading cycle; затем дополнительно проверяются GUID контрагента и организации. Epoch/identity-защиты исключают поздние callback, повторную параллельную дозагрузку и чужие строки при смене аккаунта, включая одинаковые GUID клиента/организации. Во время скрытого редактора query/status сохраняются, а запросы контроллера заблокированы. Сам контроллер не меняет draft.

CustomerStart остаётся смонтированным при открытом редакторе (`display:none`), вместо перемонтирования и потери выбора. Документ открывается существующим `selectOrder`; проверка несохранённого заказа не обходится. В desktop workspace добавлен точечный `autoSelectLatestDraft=false`: загрузка списка не выбирает автоматически последний черновик. Это не смена `screenMode` и не изменение polling, геолокации, autosave или очереди. Compact WEB сохраняет прежнее значение параметра.

`ClientOrderCustomerDocuments` использует общую `AppListPanel` с поиском, состояниями загрузки/ошибки/пустого результата, дозагрузкой и полосой прокрутки. Строка содержит номер или название черновика, дату, статус, адрес при наличии, состояние счёта при наличии и сумму. Shared delivery panel и организация из предыдущей правки сохраняются; правая шапка теперь переключает «Документы» / «Точки доставки».

Он дополняет прежние scoped snapshots, не является полным backup. Перед восстановлением требуется согласовать конкурентные изменения. Env, секреты, реальные заказы, переписки и вложения исключены.

# История реализации: прайс WEB — 7 ноября 2026

Исторический сценарий этого этапа заменял быстрый поиск с отдельной кнопкой добавления. Указания на отдельный desktop-журнал ниже заменены актуальным сценарием в начале документа.

1. Откройте «Заказы клиентов», выберите клиента и точку доставки. Нажмите «Новый заказ» или «Продолжить» у подходящего черновика.
2. Над прайсом показаны клиент, адрес, склад и дата. Изменения условий и комментарий — в «Реквизитах».
3. Ищите товар по названию/артикулу. Фильтры: «Клиент уже брал», «В наличии», «В заказе».
4. Введите абсолютное количество в колонке «В заказе». Enter и стрелки переводят к соседней строке. Весовые количества поддерживают дробь, например 1,5. Итог меняется сразу.
5. «В заказе» оставляет выбранные строки. Для удаления введите 0 и нажмите Enter. Черновик сохраняет прежний механизм браузерного хранения и автосохранения.
6. Нажмите «Проверить заказ»: клиент, точка, позиции, итог. Затем «Отправить в 1С». Состояние доступно в «Журнале».

На изолированном стенде отправка имитируется. В приложении используется существующая персональная 1С и очередь. OTA не опубликовано.

Ограничение текущего API: общий поиск клиента по адресу работает только среди загруженных записей журнала. После выбора клиента можно искать все доступные его точки доставки. Глобальный поиск по всем адресам API пока не предоставляет.

# Технический контекст: прайс заказов WEB

Новая инструкция владельца заменяет предыдущий сценарий. Главный экран теперь customers: ClientOrderCustomerStart (локальный выбор клиента/организации/точки), потом editor, отдельно orders/Журнал. Сохранён единственный workspace. Создание проходит существующую проверку несохранённых изменений, затем последовательные свежие рендеры организация→клиент/условия→точка. Защиты аккаунта, unmount, request/scope и повторных этапов. Продолжить проверяет соответствие клиента, точки и организации текущему черновику.

ClientOrderPriceGrid показывает 50 товаров за страницу, абсолютное количество, остаток/единицу/цену/сумму. Использует searchProducts и прежний purchase history contract. Фильтры склада, истории и набранных позиций. Валидный ввод сразу меняет workspace, 0 удаляет при подтверждении; IME не перехватывается. Сохраняются существующая упаковка и ручная цена, запрещены отменённые строки и мутации во время readOnly/loading/операций. Parent не открывает проверку при aria-invalid в количестве. Существующие права, storage, queue, linked readOnly и native screen не заменены.

Оформление: существующий AppWorkspaceHeader и цвета «Помощи», плоские списки/таблица без внешних карточек. Реквизиты свернуты. Диалог проверки перечисляет клиента, точку, строки и итог до существующей отправки.

Проверки:160 тестов/10 наборов, TypeScript. В браузере на синтетическом workspace: выбор клиента/точки→создание→два количества3 и4 с Enter→фильтр В заказе→удаление0→проверка→mock-submit→Журнал. API не имеет глобального адресного поиска; доступен адрес по клиенту и локальные совпадения загруженного журнала.

Источники: ClientOrdersWebScreen.tsx, desktop/ClientOrderCustomerStart.tsx, ClientOrderPriceGrid.tsx, clientOrderPriceGridModel.ts. Доказательства .dev-runtime/orders-price-workflow-20261107. Исходники и проверки — закрытый Nextcloud «Восстановление компании», orders-price-workflow-source-20261107.tar.gz. Это дополнение к прежним scoped snapshots, не полный backup. Env/секретов/рабочих диалогов нет. Metro8081 сохранён; OTA/API/native release не выполнялись.

## Историческая первая правка: только поле поиска — WEB PC, 8 ноября 2026

Этот вариант заменяется общей левой панелью ниже: одного переиспользуемого поля оказалось недостаточно для требования владельца. Показанные здесь проверки и архив относятся к первой правке.

В широкой WEB-версии поиск расположен над левым списком клиентов. Поле «Поиск» имеет ту же форму, иконку и очистку, что поиск обращений в «Помощи». Выбор организации остаётся справа. ## Общая левая панель «Помощи» и клиентов — WEB PC, 8 ноября 2026

Текущая корректировка заменяет описанный выше вариант, в котором общим было только поле поиска. ## Общие состояния списка и поиск без артефактов — 8 ноября 2026

Следующее уточнение общей панели переносит в неё представление первой загрузки, пустого списка, ошибки, повторной попытки и дозагрузки. `AppListPanelState` получает состояние и callback от сервиса; данные и сетевые запросы остаются у «Помощи»/заказов. Панель показывает 4 статичные строки skeleton при первой загрузке, отдельный индикатор дозагрузки после уже загруженных строк, пустое состояние с очисткой поиска и действие повтора после ошибки. `loadState` содержит `scope`, `itemCount`, `loading`, `hasMore`, `disabled`, `error`, `query`, подписи и callback `onLoadMore`/`onRetry`/`onClear`. `renderList` дополнительно получает `emptyState`, `footerState`, `onEndReached`, `onScroll`, `onLayout`, `onContentSizeChange`.

Общий gate предотвращает одновременную дозагрузку и повторную автоматическую попытку для того же scope + itemCount. Epoch защищает переход A→B→A и поздние ошибки; после ошибки автозагрузка не повторяется, доступен явный повтор/«Показать ещё». Геометрия привязана к epoch, числу строк и отступам: старая высота skeleton не запускает вторую страницу до измерения реальных строк. Автоматическое заполнение действительно короткого списка после свежего измерения сохраняется. Help сохраняет FlashList и запросы сервиса; для Orders ScrollView используется общий порог конца списка. Ошибка списка клиентов отделена от ошибок точки/создания заказа; отдельные `listLoading`/`listError` Help защищены identity/generation и не смешиваются с состоянием других операций.

В общем поле поиска WEB используется `AppSearchGlyph.web.tsx`: SVG в фиксированном блоке 20×20, без зависимости от метрик иконного шрифта при масштабе браузера 100%. Native glyph сохраняет Ionicons. Кнопка очистки общего поля — круг 28×28 с радиусом 14, поэтому её hover/focus-подсветка круглая.

Дополнительно статус соединения в шапке «Помощи» стал показывать только затянувшиеся сбои. Состояния checking/syncing не выводят текст, offline/sync-error появляются после 3 секунд непрерывного foreground, connecting — после 12 секунд. ready/paused/уход в фон сразу скрывают предупреждение; повтор и возвращение в foreground запускают новый интервал. Меняется только представление: сетевые попытки, синхронизация и обработчик повтора остаются прежними.

Итоговые проверки: 206 тестов в 9 наборах, 3 проверки границы fixture-сети, TypeScript, Expo Doctor 20/20, согласованные зависимости; основные bundles Metro WEB/Android HTTP 200. На изолированном синтетическом workspace в браузере 1280×800, scale=1, DPR=2 проверены SVG 20×20, круглая hover-подсветка 28×28, первая загрузка/skeleton, пустой поиск и очистка, ошибка/повтор и тёмная тема. Загрузка начинает с 30 строк и только offset=0; после прокрутки получены 60, затем 75 строк с запросами offset=0/30/60 без лишнего запроса. Точный исходный артефакт на Windows DPR=1 не воспроизводился; эта конфигурация не заявляется как проверенная.
