# Проверка и публикация базы знаний

## Где находится

- **Администрирование → База знаний** — для администратора.
- **Помощь → меню ⋯ → База знаний** — для сотрудника с правом `manage_knowledge` и доступом к «Помощи».
- Прямая страница: `/services/help/knowledge`.

Все действия обращаются к API, указанному в `EXPO_PUBLIC_API_URL_DEV`, с обычной сессией пользователя. Право проверяется сервером для каждого запроса. Секретов Nextcloud и S3 в приложении нет.

## Работа с документом

1. Положите TXT, MD, DOCX или PDF в `V:\Leader-Product-Cloud\База знаний\Материалы компании` и дождитесь синхронизации Nextcloud.
2. Откройте вкладку «На проверке». Кнопка «Синхронизировать» запрашивает ближайший обход worker; она не означает мгновенное завершение обработки.
3. Прочитайте извлечённый текст и отметьте «Я проверил текст этой версии». Просмотр показывает обычный текст, который будет использовать поиск, а не оригинальное форматирование файла.
4. Выберите доступ: только проверяющим, отдельным отделам/сотрудникам или всем сотрудникам. Получателей можно искать по именам; прямой ввод ID не требуется.
5. Подтвердите публикацию. Документ переместится в «Опубликовано». Там можно изменить доступ или отозвать публикацию, сохранив исходный файл в Nextcloud.

Если файл изменился, публиковать просмотренную старую версию нельзя. Фоновое обновление обновляет метаданные, но не подменяет читаемый текст: нужно открыть актуальную версию и проверить её заново. Сервер повторно проверяет файл в Nextcloud при публикации.

«Обработка» показывает ожидающие и выполняющиеся задания. «Ошибки» содержит причину и возможность повторной обработки. Если текст ещё не готов, используйте «Обновить текст». Во «Всех документах» можно отфильтровать папку; черновики ИИ и архив нельзя публиковать. Проверенный черновик сначала переносят в «Материалы компании» через Nextcloud.

При недоступном, отключённом или давно не синхронизированном источнике публикация блокируется. Автоматической публикации нет. История отображает последние 100 действий, версии загружаются страницами по 20.

## Реализация

- `src/features/knowledge/KnowledgeReviewPanel.tsx` — общий экран для админки и отдельной страницы.
- `useKnowledgeReview.ts` — отмена устаревших запросов, загрузка страниц, обновление метаданных каждые 15 секунд для первой страницы.
- `DocumentReader.tsx` — просмотр текста, версий и истории; длинный текст разбивается на блоки без потери символов.
- `PublicationDialog.tsx`, `AudiencePicker.tsx` — подтверждение области доступа.
- `api.ts` — обычный авторизованный HTTP-клиент приложения; изменяющие запросы не повторяются автоматически.

На телефоне список и документ открываются последовательно; на широком экране показываются рядом. Подтверждение и действия остаются внизу, текст прокручивается отдельно.

## Проверка и текущий выпуск

31.10.2026 проверены реальные компоненты в браузере на ширине 390 и 1440 px: публикация с отделом и сотрудником, история, отзыв, повтор обработки, ошибка 409, старая версия, недоступность источника и отказ в доступе. TypeScript проверен в APP и API; отдельно проверены ограничения публикации и сохранность длинного текста.

Новые запросы каталога/версий/получателей выпущены в dev API (`leader-api-knowledge-review:20261031`). Android APK и production frontend в этой задаче не выпускались; для установленного приложения нужен запуск актуального исходного кода или новый обычный выпуск APP.

Для быстрого просмотра интерфейса есть отдельный стенд на данных примера: `npm run qa:knowledge`, адрес `http://localhost:8102`. Он использует те же компоненты, но не подключён к реальным документам и не меняет базу. Подробнее — `qa/knowledge-preview/README.md`.

Эта часть добавляет проверку документов. Подключение опубликованных материалов к реальной модели ответов ИИ выполняется отдельным следующим этапом.
