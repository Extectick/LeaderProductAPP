# Оформление сообщений Help

Обновление 07.11.2026 объединяет представление обычных сообщений, ответов ИИ, хода работы и истории уточнений. Использованы общие приёмы установленного T3 0.1.7: нейтральное пользовательское сообщение, ответ ассистента без повторяющейся крупной шапки, компактные раскрываемые строки работы и вопросов. Точное визуальное соответствие официальному Codex не установлено; это адаптация к интерфейсу LeaderProduct, не заявление о пиксельной копии.

## Ответы и ход работы ИИ

Готовый ответ больше не повторяет крупный аватар и видимый заголовок «ИИ ассистент» перед каждым сообщением. Роль сохраняется в доступном для assistive technology заголовке. Для активного или служебного состояния используется компактная строка; reduced motion учитывается существующей темой.

`HelpAssistantProgress` показывает текущее публичное действие и историю действий во время thinking/streaming. С 12.11.2026 история раскрыта по умолчанию для каждого нового run. Ручное сворачивание сохраняется в пределах текущего run и не отменяется следующими фрагментами ответа; следующий run снова раскрывается. Список ограничен высотой 260 и сохраняет ручную прокрутку: чтение более ранних действий останавливает следование вниз, возвращение к концу возобновляет его. Используются уже доступные публичные активности и analysis, новый источник внутренних рассуждений не добавляется. Завершённый run не оставляет постоянно раскрытый журнал перед ответом.

На web используется тот же `AppWebScrollbar`, что и в списке обращений: узкий округлый ползунок без системных стрелок и фона дорожки, с существующими hover/drag и клавиатурными действиями. Системный web-индикатор скрыт. Ползунок связан с собственным scroll-узлом конкретного сообщения; native сохраняет свой индикатор и жесты.

Обычный и live-ответы согласованы по отступам: горизонтально 16, сверху 16, снизу 12. Markdown использует lineHeight 24 для основного текста и вертикальные отступы абзацев 5; существующие ссылки, код, таблицы и выделение текста сохраняются.

## Код в сообщениях

Ответы ИИ уже поддерживают Markdown: встроенный код в обратных кавычках, fenced-блоки из трёх обратных кавычек и блоки с отступом. `HelpMarkdown` отображает моноширинный текст на отдельном фоне, подпись языка, выделение текста и горизонтальную прокрутку. Синтаксической подсветки и отдельной кнопки копирования блока пока нет. Потоковое отображение учитывает ещё не закрытые fenced-блоки и сохраняет идентичность готовых блоков при завершении ответа. Публичный анализ и пользовательские сообщения выводятся обычным текстом: Markdown-код оформляется именно в теле ответа ИИ.

## История уточнений

`HelpAssistantQuestionStatus` показывает реальный текст одного вопроса либо количество вопросов и статус. Раскрытие показывает вопросы и варианты в режиме чтения. Ответы по-прежнему вводятся через существующую панель вопросов/composer; история не отправляет ответы, не меняет черновики и не продвигает анкету.

Статус истории определяется по последующему содержательному USER-сообщению владельца обращения, а не по текущему наблюдателю. Поэтому администратор, открывающий чужую переписку, видит тот же статус, что и владелец. `helpQuestionReplySequence` исключает другие обращения, служебные статусы, ответы ИИ и пустые сообщения; учитывает lastMessage при просмотре старого окна истории. Это признак наличия последующего ответа для отображения, не отдельное подтверждение выполнения каждого вопроса.

## Сообщения пользователя

Исходящие сообщения используют нейтральный фон темы `elevated`, радиус 20 и групповые отступы 12/8. На desktop текстовое сообщение ограничено 80% доступной ширины, на мобильных платформах и для медиа сохраняется 86%. Подпись к фотографии остаётся независимой от узкой ширины портретного изображения; геометрия media/caption и отметок времени не перестраивается по размеру загруженной картинки. Существующие реакции, действия сообщения, загрузка файлов и доступность сохраняются.

## Края изображения без цветных боковых полос

Дополнение 07.11.2026: блок фото с подписью теперь ограничен той же шириной mediaBounds (до 640), что и само превью. Альбом и широкое изображение доходят до края общей рамки. Портрет сохраняет пропорции, а подпись может быть шире него; свободное место по бокам изображения прозрачно. Фон остаётся у подписи, а не у всей области фотографии. Узкий портрет в собственном сообщении выравнивается по правому краю, во входящем — по левому; размеры, скругления и ширина подписи при этом не меняются. Проверки этого выравнивания: 49 тестов в 2 наборах, TypeScript, Expo Doctor 20/20 и оба Metro bundle HTTP 200; доказательства — `.dev-runtime/help-image-alignment/`.

Изображение обрезается внутренней обёрткой по существующим углам сообщения. Если подпись шире портрета, она получает собственное скругление; когда фото и подпись имеют одну ширину, сохраняется единое соединение блоков. Photo-only, отметка времени поверх изображения, открытие галереи и жесты остаются прежними. Это APP-правка без API deployment, OTA и перезапуска сервисов; отдельная визуальная browser/native QA для дополнения не заявляется. Для дополнения пройдены 73 теста в 4 наборах и TypeScript, Expo Doctor 20/20, зависимости актуальны. Оба финальных Metro bundle вернули HTTP 200 и содержат округлённую image-clip обёртку. Итоговые доказательства и небольшой архив находятся в `.dev-runtime/help-image-edges/`.
