# Ссылки на объекты и общая панель просмотра

Нативный Gorhom PortalHost находится выше Auth/Theme провайдеров приложения.
`EntityCardPortalContext` переносит в карточку контексты исходной сессии, темы
и навигации: без этой границы вошедший сотрудник внутри панели выглядел гостем.
Открытие панели требует действующей сессии, а не выбранного типа профиля;
просмотр чужого профиля сотрудником проверяет прежний `/users/:id/profile`.
Объект EntityCardContext сохраняет идентичность при Metro Fast Refresh.

`EntityCardProvider` расположен под AuthProvider над текущими маршрутами.
`useEntityCards().openEntity(target, label)` открывает карточку поверх приложения;
`openEntityLink(url, label)` разбирает тот же версионированный URI. HelpMarkdown
использует этот механизм для сохранённых и потоковых ответов ИИ. Обычные HTTP
ссылки сохраняют прежнее поведение. Неизвестный внутренний формат не открывает
произвольный маршрут.

## Контракт идентичности

```ts
type EntityTarget =
  | {v:1;source:'onec';baseKey:string;metaType:EntityOnecType;name:string;guid:string}
  | {v:1;source:'app';kind:'user';id:string}
  | {v:1;source:'app';kind:'product';guid:string};
```

Codec: `src/shared/entityLinks.ts`, синхронен контракту API. URI:

```text
leaderproduct://entity/v1/onec/<baseKey>/<metaType>/<encodedName>/<guid>
leaderproduct://entity/v1/user/<appUserId>
leaderproduct://entity/v1/product/<productGuid>
```

База является частью идентичности 1С; GUID сотрудника 1С не является APP user ID.
URI не содержит токенов, паролей и полномочий. Сохранённая ссылка при открытии
читает актуальные данные с текущим доступом пользователя. `+native-intent`
перенаправляет только этот формат на `entity-link`; одиночное ожидающее
намерение переживает переход к авторизации без хранения учётных данных.

## Панель и карточки

HTML-просмотр, профиль и карточки 1С используют один `HelpViewerLayout`:
прозрачная плавающая шапка с общим блюром, округлая поверхность с коротким названием страницы
в центре, стрелка слева и постоянные три точки справа. Цвет поверхности задан
обычным вариантом `HelpHeaderFrame`, как в чате, без отдельной белой заливки.
`HelpHeaderOverlay` один для списка обращений, чата, HTML и карточек: он задаёт
системный отступ, захват содержимого и нижний край блюра. Изменения оформления
применяются везде через эти общие компоненты. Отдельной разметки `EntityCardHeader`, ручки,
крестика и разделительной линии больше нет. Начальный отступ тела равен общей
высоте шапки; при прокрутке содержимое проходит под ней.

Native сохраняет установленный Gorhom BottomSheet, его согласованные жесты
и BottomSheetScrollView / BottomSheetFlatList. Фон панели доходит до самого верхнего края без внешней белой полосы;
кнопки и исходное содержимое учитывают системный верхний inset ровно один раз.
Панель имеет историю с кнопкой «Назад». Из прокрученного содержимого жест сначала прокручивает
к началу. Web использует ту же историю, тот же `HelpViewerLayout` и карточки
в своей жестовой оболочке. Стрелка возвращает предыдущую карточку либо закрывает
последнюю; «Закрыть просмотр» в общем меню закрывает всю историю. Старый callback
dismiss не закрывает новый сеанс.

«Ссылка» в меню копирует только канонический URI текущей карточки. Перед
копированием повторно проверяются текущий пользователь, токен, отмена, аккаунт
и активная карточка; поздний ответ после перехода не показывает старое уведомление.
У защищённой формы подключения 1С ссылки нет. Генерация файлов для профиля или
заказа в это изменение не входит: «Скачать» относится к настоящему HTML-файлу.

Маршруты и черновики под панелью не размонтируются. Help временно приостанавливает
фокус composer и фоновые жесты чата, сохраняя существующего владельца IME/tail.
Позиции карточек хранятся в ref без React-render на каждом кадре scroll.
Смена аккаунта сразу скрывает старое содержимое и отменяет его загрузки.

Реестр `entityCardRegistry` содержит product/client-order/generic renderer.
Карточки 1С получают поля, таблицы и типизированные ссылки через личный resolver;
редактор заказов и локальная очередь не монтируются.
Профиль использует существующий ProfileView с явным userId в режиме просмотра.
Новый renderer регистрируется отдельно от оболочки и URI codec.

Табличные части загружаются порциями 100 → 250 → 1000, с явным признаком
неполноты. Расширение не превращает ограниченный ответ в подтверждение полного
состава. Защищённая форма подключения 1С открывается в той же истории, затем
возвращает к повторной загрузке карточки; пароль не проходит через чат.

## Проверки

Тесты: entityLinks, entityCardState, entityCardProvider, entityCards, helpMarkdown.
Изолированный Android-стенд `qa/entity-preview` использует настоящие компоненты
с синтетическими адаптерами и заблокированной сетью. В этой сессии его Metro
bundle проверен, но визуальная проверка жестов на устройстве недоступна:
Device MCP вернул DEVICE_IN_USE после разрешённого повторного ожидания.
Это не подтверждение нативного поведения жестов на телефоне.


## Карточка из «Остатки по складам» — Metro, 2026-11-05

APP product и прежние ссылки Catalogs.Номенклатура открывают StockEntityCard
через точный GET /stock-balances/products/:guid. Для старой ссылки передаётся
baseKey; сервер обязан подтвердить привязку базы, иначе409. Ошибка не заменяется
поиском по имени или личной generic-карточкой1С. Смена аккаунта отменяет запросы.

StockProductsScreen и StockEntityCard используют один StockProductDetails:
фото/галерея, склады, остатки, приходы/расходы и цены сохраняют поведение сервиса.
Только активная вкладка регистрирует Gorhom list focusHook, чтобы скрытый список
не перехватывал закрывающий жест. Панель резервирует общую высоту шапки.
Заголовок обновляется проверенным названием товара/профиля и ограничен44символами;
ИИ получает инструкцию давать короткую подпись подтверждённой ссылки.

У шапки общий AppEdgeBlur и собственный activity context для портала;
HTML Modal аппаратно ускорен, как основное окно. Новая OTA не публиковалась.

## Заказ из ссылки — источник и штатное представление, 06.11.2026

Ссылки `onec/<baseKey>/Documents/ЗаказКлиента/<guid>` проходят проверку через
`GET /api/client-orders/:guid?baseKey=...`. Это личная MCP-база из исходной ссылки:
`sourceBaseKey`, GUID и `readOnly=true` сверяются до открытия. Нет преобразования
GUID в заказ другой публикации или fallback через WMS15. Generic `get_object`
не требуется: большое представление документа вызывало `ONEC_RESPONSE_TOO_LARGE`
в обращении77.

После проверки общий provider сохраняет окно: `EntityCardContent` показывает
штатный `ClientOrderReadOnlyView` из сервиса заказов прямо внутри него. Автоматического
router.push и закрытия панели больше нет. Проверенный документ из первого запроса
передаётся в представление без повторной загрузки. Исходный Help, позиция списка
и несохранённое сообщение остаются смонтированными; Back возвращает к предыдущей
карточке, закрытие — к чату. Account/AbortSignal fences сохраняются.

Общий `classifyAppLink` обрабатывает как entity-ссылки заказа, так и HTTPS
`https://app.dev.lidprod.ru/services/client_orders?orderGuid=<guid>&orderBaseKey=<baseKey>`
и `leaderproduct://services/client_orders` с теми же параметрами. Исходная база
обязательна; принимаются только уникальные известные параметры и допустимый GUID.
Это применяется к кликам Markdown, HTML и вложенным ссылкам общего просмотрщика.
Прямое открытие URL в адресной строке по-прежнему открывает защищённый маршрут.

Маршрут с `orderBaseKey` использует `ClientOrderLinkedScreen`; он не монтирует
редакторский `useClientOrdersWorkspace`, списки, lookup/reference-запросы,
локальные очереди, обогащение товаров, счета или операции записи. Его
`ClientOrderReadOnlyView` экспортирован из прежнего `ClientOrdersMobileScreen`:
используются те же `HeaderSection`, `ItemsSection`, `LineItemCard` и `orderToDraft`.
Invoice-компонент и раскрытие чужих references отключены. Неподтверждённые
изображения из другой публикации не загружаются. Валюта отображается по источнику,
частичные строки и сокращённый комментарий явно отмечаются через
`sourceTruncated`/`commentTruncated`/`readOnlyReason`. Readonly adapter сохраняет
фактические `price`/`lineAmount` после штатного `orderToDraft`; источник сумм
не заменяется расчётом из справочных цен. Фон страницы, загрузки и новых частей
представления использует ту же палитру `useThemeColor`, что обычный сервис.

Запросы закреплены за APP-аккаунтом, выбранной базой и AbortSignal. Отсутствующее
личное подключение открывает прежнюю защищённую `ProfileOnecConnections` для
этой базы; поздний ответ старой сессии не показывает документ. Back возвращает
к исходному экрану. Обычный сервис без `orderBaseKey` сохраняет свой прежний
редактор, разрешения и очередь. Нативный runtime и OTA не менялись.
