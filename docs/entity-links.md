# Ссылки на объекты и общая панель просмотра

Нативный Gorhom PortalHost находится выше Auth/Theme провайдеров приложения.
`EntityCardPortalContext` переносит в карточку контексты исходной сессии, темы
и навигации: без этой границы вошедший сотрудник внутри панели выглядел гостем.
Открытие панели требует действующей сессии, а не выбранного типа профиля;
просмотр чужого профиля сотрудником проверяет прежний `/users/:id/profile`.
Объект EntityCardContext сохраняет идентичность при Metro Fast Refresh.

`EntityCardProvider` расположен под AuthProvider над текущими маршрутами.
`useEntityCards().openEntity(target, label)` открывает карточку поверх приложения;
`openEntityLink(url, label)` разбирает тот же версионированный URI. HelpMarkdown
использует этот механизм для сохранённых и потоковых ответов ИИ. Обычные HTTP
ссылки сохраняют прежнее поведение. Неизвестный внутренний формат не открывает
произвольный маршрут.

## Контракт идентичности

```ts
type EntityTarget =
  | {v:1;source:'onec';baseKey:string;metaType:EntityOnecType;name:string;guid:string}
  | {v:1;source:'app';kind:'user';id:string};
```

Codec: `src/shared/entityLinks.ts`, синхронен контракту API. URI:

```text
leaderproduct://entity/v1/onec/<baseKey>/<metaType>/<encodedName>/<guid>
leaderproduct://entity/v1/user/<appUserId>
```

База является частью идентичности 1С; GUID сотрудника 1С не является APP user ID.
URI не содержит токенов, паролей и полномочий. Сохранённая ссылка при открытии
читает актуальные данные с текущим доступом пользователя. `+native-intent`
перенаправляет только этот формат на `entity-link`; одиночное ожидающее
намерение переживает переход к авторизации без хранения учётных данных.

## Панель и карточки

HTML-просмотр, профиль и карточки 1С используют один `HelpViewerLayout`:
прозрачная плавающая шапка с общим блюром, «Просмотр» в центре, стрелка слева
и постоянные три точки справа. Это тот же `HelpHeaderFrame`, что и в чате,
с прозрачной областью заголовка. Отдельной разметки `EntityCardHeader`, ручки,
крестика и разделительной линии больше нет. Начальный отступ тела равен общей
высоте шапки; при прокрутке содержимое проходит под ней.

Native сохраняет установленный Gorhom BottomSheet, его согласованные жесты
и BottomSheetScrollView. Панель доходит до верхней безопасной границы и имеет
историю с кнопкой «Назад». Из прокрученного содержимого жест сначала прокручивает
к началу. Web использует ту же историю, тот же `HelpViewerLayout` и карточки
в своей жестовой оболочке. Стрелка возвращает предыдущую карточку либо закрывает
последнюю; «Закрыть просмотр» в общем меню закрывает всю историю. Старый callback
dismiss не закрывает новый сеанс.

«Ссылка» в меню копирует только канонический URI текущей карточки. Перед
копированием повторно проверяются текущий пользователь, токен, отмена, аккаунт
и активная карточка; поздний ответ после перехода не показывает старое уведомление.
У защищённой формы подключения 1С ссылки нет. Генерация файлов для профиля или
заказа в это изменение не входит: «Скачать» относится к настоящему HTML-файлу.

Маршруты и черновики под панелью не размонтируются. Help временно приостанавливает
фокус composer и фоновые жесты чата, сохраняя существующего владельца IME/tail.
Позиции карточек хранятся в ref без React-render на каждом кадре scroll.
Смена аккаунта сразу скрывает старое содержимое и отменяет его загрузки.

Реестр `entityCardRegistry` содержит product/client-order/generic renderer.
Карточки 1С получают поля, таблицы и типизированные ссылки через личный resolver;
редактор заказов, локальная очередь и складское зеркало не монтируются.
Профиль использует существующий ProfileView с явным userId в режиме просмотра.
Новый renderer регистрируется отдельно от оболочки и URI codec.

Табличные части загружаются порциями 100 → 250 → 1000, с явным признаком
неполноты. Расширение не превращает ограниченный ответ в подтверждение полного
состава. Защищённая форма подключения 1С открывается в той же истории, затем
возвращает к повторной загрузке карточки; пароль не проходит через чат.

## Проверки

Тесты: entityLinks, entityCardState, entityCardProvider, entityCards, helpMarkdown.
Изолированный Android-стенд `qa/entity-preview` использует настоящие компоненты
с синтетическими адаптерами и заблокированной сетью. В этой сессии его Metro
bundle проверен, но визуальная проверка жестов на устройстве недоступна:
Device MCP вернул DEVICE_IN_USE после разрешённого повторного ожидания.
Это не подтверждение нативного поведения жестов на телефоне.
