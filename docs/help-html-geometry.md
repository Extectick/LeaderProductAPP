# Стабильная высота HTML в Help

Исправление обращения №50, 07.11.2026. Раньше размер загрузочного блока мог отличаться от размера HTML после скачивания и разбора CSS, поэтому сообщение меняло высоту. Необязательная фотография или смена темы также могли повторно включать скелетон уже показанного документа.

## Размер до скачивания

`HelpHtmlMessage` выбирает геометрию только из метаданных вложения, доступных в истории и sync: конечная высота от 48 до 1200 включительно либо квадрат по ширине контейнера. Загрузка JSON/CSS, кеш, фотография и ошибка скачивания не меняют выбранную геометрию. Для документа только с полноэкранной версией сервер сохраняет высоту 48; после загрузки в той же области появляется ссылка. У старого документа без корректной высоты сохраняется квадратный fallback.

API сохраняет размеры до публикации вложения. Новый `help.html-geometry.ts` извлекает явно заданную высоту в px только у единственного корневого элемента: inline style либо простые селекторы тега, класса и id. Учитываются порядок правил, специфичность и `!important`; сложные условные правила и неопределённая геометрия дают квадрат. Это ограниченный разбор, а не полноценный CSS layout engine. Размеры дочерних элементов не определяют высоту карточки. Допустимая дробная высота округляется вверх, поскольку размеры вложения хранятся как Prisma Int. Квадрат кодируется как width=1, height=1; полноэкранный документ без compact — width=null, height=48.

## Скелетон документа

`HelpHtmlSurface` связывает готовность отображения с HTML/CSS варианта, compact и верхним отступом. Фотография и тема обновляют содержимое, но не возвращают скелетон поверх уже показанного документа. Новый вариант получает новое состояние готовности. Ограничения iframe/WebView, запрет JavaScript и существующая обработка ссылок сохраняются; новый измеряющий скрипт не добавлен.

## Существующие сообщения и runtime

В dev обработаны 20 существующих HTML-вложений: 15 получили фиксированную высоту, 5 — квадрат. Содержимое HTML и пользовательские тексты не менялись. Отправлено 12 обычных событий MESSAGE_UPDATED, без уведомлений. Повторный dry-run не нашёл изменений. Sync обращения №50 отдаёт 1×1, проверенная карточка №83 — height=140.

Оба процесса API и worker переведены на `leaderproductapi:help-html-geometry50-dev-20261107-r1` и healthy. Хеши обоих модулей совпадают с подготовленным кодом, включая округление дробной высоты. Сравнение с фактическим базовым образом `leaderproductapi:help-cards83-dev-20261107-r1` подтвердило только замену help.ai-files.js и добавление help.html-geometry.js; 1275 остальных файлов dist побайтно совпадают. Не связанные с задачей контейнеры не менялись. Новые HTML-вложения получают геометрию при публикации. Серверный rollback-снимок сохранён под `/opt/leader-api-dev/backups/help-html-geometry50-20261107T102437Z`; приватную конфигурацию и данные из него не включать в обычную техническую документацию.

## Проверки и восстановление

APP: 81 тест в 4 наборах; API: 75 тестов в 3 наборах, включая дробную геометрию. TypeScript в обоих проектах прошёл, Expo Doctor 20/20, зависимости актуальны. Состояние серверного runtime и результаты bundle-запросов сохраняются в `.dev-runtime/help-html50/final-proof.json` и связанных журналах. Metro вернул HTTP 200 для Android и web, оба bundle непустые. Это проверка сборки; визуальная проверка в браузере или на нативном устройстве не заявляется. OTA и native release не публикуются.

Основные файлы: APP `HelpHtmlMessage.tsx`, `HelpHtmlSurface.tsx` в `src/features/help/components`; API `help.ai-files.ts`, `help.html-geometry.ts` в `src/modules/help`. Техническая инструкция хранится в Nextcloud с доступом IT/admin. Ограниченный архив исходников, серверных runtime-модулей, помощника backfill и доказательств хранится в закрытой папке «Восстановление компании». Снимок может включать сохранённые конкурентные изменения; перед восстановлением согласовать его с актуальной веткой. Архив не содержит env, ключей, паролей, токенов, переписок, пользовательских файлов или скриншотов.
