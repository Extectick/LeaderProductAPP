# Администрирование

`screen/AdminScreen.tsx` — маршрут приложения и существующая проверка `useIsAdmin`. `LiveAdminProvider` подключает реальные API; сервер по-прежнему проверяет права каждого действия. Приложение не импортирует fixture или код из `qa/`.

- `AdminDirectory` сохраняет каталог под разделом; переходы используют общий с Help `AppSceneTransition`.
- `AdminSceneHeader` и `AdminDesignPrimitives` задают общую сетку, прозрачную шапку, AppEdgeBlur, редакторы и настоящий HelpSheet.
- `AdminUsers`, `AdminUserIntegrations` — каталог, полная карточка, модерация, роли/отдел, статусы профилей, справочники 1С, Telegram/MAX ID и отдельный сброс пароля.
- `AdminOrganization`, `AdminServices` — отделы, роли/наследование, серверный каталог прав и настройки сервисов. Изменение имени сервиса не заменяет его правила доступа; при изменении разрешающих ролей/отделов сохраняются явные запреты и индивидуальные правила.
- `AdminContent` — чтение документов без публикации/редактирования. Отсутствующая серверная база знаний показана отдельно от остальных разделов.
- `AdminUpdates` — реальные APK и OTA из `/updates` и `/ota`; группировка учитывает runtime, платформу и канал. Для OTA используются сохранённые SHA и каталог Git, для неизвестных коммитов — описание из API. APK без SHA не получает выдуманную привязку к Git.

Каталог пользователей загружается ограниченными серверными страницами по 100 записей. Профиль сотрудника загружается отдельно перед редактированием. Остальные ресурсы загружаются при открытии раздела. Ошибки остаются видимыми с повторной попыткой. Успех показывается только после завершения запроса; формы защищены от повторной отправки. Пароль живёт только в состоянии открытой формы и передаётся существующему административному HTTPS endpoint; в кэш/fixture/историю не записывается.

`scripts/createAdminGitCatalog.cjs` формирует публичные Git subjects/parents для истории OTA; запускается перед CI-экспортом. Не читает .env, содержимое документов, ключи или пароли. Генерируемые сведения не утверждают, что коммит был опубликован: факт выпуска берётся из API.

Тот же UI используется стендом `qa/admin-preview` через `FixtureAdminProvider`. `npm run qa:admin` запускает его на 8110; fixture остаётся локальным и не вызывает рабочие API. Изменение общего компонента сразу отражается в приложении и стенде.
